# MPS-EfficientTAM

A Swift 5.9 package implementing EfficientTAM Tiny 512 image prompting
directly with Metal Performance Shaders Graph.

The package includes separate, composable GPU stages for image encoding,
point/box decoding, iterative mask prompting, and official mask resizing. It
is not yet a video tracker.

## Current scope

- Official `efficienttam_ti_512x512` image encoder architecture and weights.
- 12 ViT blocks with the upstream window/global-attention schedule.
- Upstream ImageNet preprocessing and learned `no_mem_embed` addition.
- Point and box prompt embeddings, two-way transformer, mask hypernetworks,
  three 128x128 mask-logit outputs, and predicted IoU scores.
- Iterative prompting from one prior 128x128 mask-logit plane through the
  official learned mask-downscaling path.
- Official bilinear resizing of raw mask logits to a caller-selected output
  size (`align_corners=false`), kept separate from decoding.
- Float32 transformer intermediates for accuracy. EfficientTAM's image encoder
  has known severe accuracy degradation when indiscriminately converted to
  FP16.
- A synchronous `run`, asynchronous `submit`, and GPU-resident `encode` API
  matching the other Fabric MPS packages.
- No CPU/GPU synchronization in `encode`; in-flight saturation drops work by
  returning `false` rather than blocking.
- Full-tensor accuracy testing against an output generated by the official
  PyTorch implementation's Apple-MPS behavior.

The image encoder outputs a float32 NCHW embedding with shape
`[1, 256, 32, 32]`. Cache it and reuse it with `EfficientTAMPromptDecoder`.
Every GPU stage accepts caller-owned buffers and command buffers, so clients
can schedule each stage independently or compose them into a larger graph.

## Requirements

- macOS 15, iOS 18, or visionOS 2
- Swift 5.9
- A Metal device

## Usage

```swift
import Metal
import MPSEfficientTAM

let device = MTLCreateSystemDefaultDevice()!
let commandQueue = device.makeCommandQueue()!
let encoder = try EfficientTAMImageEncoder(commandQueue: commandQueue)

let commandBuffer = commandQueue.makeCommandBuffer()!
let output = device.makeBuffer(
    length: encoder.outputBufferLength,
    options: .storageModePrivate
)!

let accepted = try encoder.encode(
    inputBuffer: rgbFloat32NHWCBuffer,
    outputBuffer: output,
    commandBuffer: commandBuffer,
    commit: true
)

let decoder = try EfficientTAMPromptDecoder(promptCount: 2, commandQueue: commandQueue)
let prediction = try decoder.run(
    imageEmbeddingBuffer: output,
    prompts: [
        .init(x: 160, y: 240, label: .positivePoint),
        .init(x: 0, y: 0, label: .padding),
    ]
)
```

For iterative refinement, encode a selected prior mask and pass its dense
embedding to the decoder:

```swift
let maskPromptEncoder = try EfficientTAMMaskPromptEncoder(commandQueue: commandQueue)
let densePrompt = device.makeBuffer(
    length: maskPromptEncoder.outputBufferLength,
    options: .storageModePrivate
)!
let maskPromptCommandBuffer = commandQueue.makeCommandBuffer()!

_ = try maskPromptEncoder.encode(
    maskLogitsBuffer: prior128x128Logits,
    densePromptEmbeddingBuffer: densePrompt,
    commandBuffer: maskPromptCommandBuffer,
    commit: true
)

let refinedPrediction = try decoder.run(
    imageEmbeddingBuffer: output,
    prompts: prompts,
    densePromptEmbeddingBuffer: densePrompt
)
```

`EfficientTAMMaskPostprocessor` resizes one or more 128x128 mask-logit planes
without thresholding them. `binaryMask(from:threshold:)` is available after
CPU readback, while GPU clients can keep the logits resident for their own
filtering or compositing.

The package deliberately does not include guided-image or joint-bilateral
refinement. Those are useful downstream composition choices, but are not part
of EfficientTAM's core learned mask path. Fabric can expose them as separate
nodes without coupling third-party package users to Fabric.

`inputBuffer` is tightly packed float32 RGB in NHWC order, 512x512, with
values in `0...1`. The model performs ImageNet normalization internally.

`run(inputBuffer:)` is an offline/testing convenience that returns a Swift
array and therefore waits for GPU completion. Real-time consumers should use
`encode` or `submit`.

## Command-buffer ownership

When `commit` is `true`, the package commits through its internal
`MPSCommandBuffer` wrapper. Do not commit the raw command buffer again.

When `commit` is `false`, the caller retains commit responsibility. MPSGraph
may internally split a large executable across command buffers; consumers
should treat the passed command buffer as dedicated to this inference call,
consistent with the existing Fabric MPS modules.

## Accuracy tests

```sh
swift test
```

The differential tests compare all 262,144 image-embedding values, all 262,144
dense mask-prompt values, complete multimask logits and IoU predictions, and
a non-square resized-logit output to official PyTorch outputs. They also test
an entirely GPU-resident mask-prompt → decoder → postprocessor chain with no
intervening CPU waits. Fixture generators live in `Tools`;
`Tools/export_weights.py` recreates the native mapped-weight files from the
official checkpoint.

## Roadmap

1. Video memory encoder and efficient memory attention.
2. Stateful video tracking with explicit reset and bounded frames in flight.

Fabric node integration should still wait until the image API is exercised in
the package and its buffer-lifetime contract is stable.
